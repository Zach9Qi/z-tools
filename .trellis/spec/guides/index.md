## 何时触发思考

**跨层**(读 cross-layer 指南):

- [ ] 改动同时触及 `.vue` 与 `.rs`。
- [ ] 数据格式在层间变化(Rust 结构体 → TS 类型 → 组件展示)。
- [ ] 新增命令、事件、`AppError` 变体、配置字段。
- [ ] 组件或命令开始对 payload 字段做 `as X` 强转 / 手动解析。

**复用**(读 code-reuse 指南):

- [ ] 正在写的东西和已有代码很像。
- [ ] 同一模式出现第 3 次。
- [ ] 要改一个常量 / 事件名 / 命令名 / 错误文案 —— **先 grep 前后端两侧**。
- [ ] 新建工具函数之前 —— 先搜 `src/lib/`、`src-tauri/src/`。

## 改值先搜索

```bash
grep -rn "要改的值" src src-tauri/src scripts
```

命令名、事件名、错误文案、配置键都在前后端各有一份,漏改一侧不会有编译错误,只会在运行时静默失效。

## 校验 AI 交叉评审结果

- 评审说「用户输入可能是恶意的」→ 看数据源:来自前端 `invoke` 参数(不可信,需校验)还是 Rust 内部 / 打包资源(可信)。
- 评审说「缺少校验」→ 信任边界在 Rust 命令层;前端对 Rust 返回值不做二次校验是设计。
- 评审说「行为变更」→ 读代码注释,是否为有意为之的设计。
- 评审说测试有 bug → 把被测功能删掉再想:测试还能过吗?能过就是同义反复测试。

每条 CRITICAL / WARNING 都要对照真实代码核实后再排优先级;AI 评审的假阳性率按大约三分之一预估。

## 维护

- 发现新的「没想到」→ 把它加进对应指南,附真实文件路径。
- 业界无统一做法且本仓库尚未选择的,写进各层 `index.md` 的「关键决策记录」并标「暂不规定」,不要在业务任务里顺手拍板。
